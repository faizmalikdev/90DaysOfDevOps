# Day 08 – Cloud Server Setup: Docker, Nginx & Web Deployment

## Task

Today I deployed and configured a real web server on a cloud instance. I connected to the server using SSH, installed and configured Nginx, allowed HTTP traffic through the cloud security group, verified the Nginx webpage from the internet, and collected Nginx logs into a separate file.

Docker was part of today's task, but I have not installed it yet. I will complete the Docker installation separately after documenting the completed Nginx deployment.

---

## Cloud Server Setup

I used an Ubuntu cloud instance and connected to it remotely using SSH.

The SSH connection allowed me to manage the cloud server directly from my local machine.

Example command:

```bash
ssh -i "your-key.pem" ubuntu@<your-instance-ip>
```

After connecting successfully, I verified that I was working inside the remote Ubuntu server.

---

## Commands Used

### 1. Update the System

First, I updated the package information on the Ubuntu server.

```bash
sudo apt update
```

I also upgraded the available packages:

```bash
sudo apt upgrade -y
```

---

### 2. Install Nginx

I installed Nginx using the Ubuntu package manager:

```bash
sudo apt install nginx -y
```

After installation, I checked whether the Nginx service was running:

```bash
sudo systemctl status nginx
```

Nginx was running successfully.

I also enabled Nginx so that it can start automatically when the server boots:

```bash
sudo systemctl enable nginx
```

---

### 3. Test Nginx Locally

I tested the Nginx server from inside the cloud instance:

```bash
curl localhost
```

This returned the Nginx welcome page HTML, confirming that Nginx was working correctly on the server.

---

## Security Group Configuration

To make the Nginx webpage accessible from the internet, I configured the cloud instance security group to allow HTTP traffic.

The rule used was:

```text
Type: HTTP
Protocol: TCP
Port: 80
Source: 0.0.0.0/0
```

Port 80 is the default port used for HTTP traffic.

After allowing port 80, I opened the public IP address of the cloud instance in my browser:

```text
http://<your-instance-ip>
```

The Nginx welcome page was displayed successfully.

## Nginx Logs

Nginx stores its logs inside:

```bash
/var/log/nginx/
```

I checked the available log files using:

```bash
ls /var/log/nginx/
```

The main log files are:

```text
access.log
error.log
```

### Access Log

The access log contains information about requests received by the Nginx server.

I viewed it using:

```bash
sudo cat /var/log/nginx/access.log
```

### Error Log

The error log contains errors and other messages generated by Nginx.

I viewed it using:

```bash
sudo cat /var/log/nginx/error.log
```

---

## Saving Nginx Logs

I combined the access and error logs into a single file named:

```text
nginx-logs.txt
```

Command used:

```bash
sudo cat /var/log/nginx/access.log /var/log/nginx/error.log > ~/nginx-logs.txt
```

I verified the file using:

```bash
cat ~/nginx-logs.txt
```

I also checked the file details:

```bash
ls -lh ~/nginx-logs.txt
```

### Screenshot

The screenshot shows the contents of the generated log file.

## Downloading the Log File

After creating the log file on the cloud server, I downloaded it to my local machine using `scp`.

From my local terminal:

```bash
scp -i "your-key.pem" ubuntu@<your-instance-ip>:~/nginx-logs.txt .
```

The `.` at the end means the file is copied to the current local directory.

## Challenges Faced

One of the main things I had to understand was the difference between the cloud security group and the Nginx service.

Nginx can be running correctly on the server, but the webpage will not be accessible from the internet if port 80 is blocked by the security group.

I solved this by allowing HTTP traffic on port 80 and then testing the server using its public IP address.

I also learned how to locate Nginx logs and save them into a separate file for later analysis.

## Why This Matters for DevOps

This exercise helped me understand the basic workflow of deploying a web server on the cloud.

In real DevOps environments, engineers regularly work with cloud servers, SSH, web servers, networking, security rules, and application logs.

The workflow I practiced today was:

```text
Cloud Instance
      ↓
      SSH
      ↓
Ubuntu Server
      ↓
    Nginx
      ↓
   Port 80
      ↓
Internet
      ↓
Web Browser
      ↓
Nginx Access/Error Logs
```

These are important foundations for later DevOps topics such as Docker, CI/CD, reverse proxies, monitoring, and cloud infrastructure.
