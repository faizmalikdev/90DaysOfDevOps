Day 05 — Linux Troubleshooting Drill
Target Service

We will use:

cron

Why cron? Because we already checked it on Day 04, and your system showed:

Active: active (running)
Main PID: 151

So we can continue troubleshooting the same service.

Step 1 — Environment Basics
1. Check Linux system information
uname -a

Purpose: Shows kernel version, architecture, hostname, and other system information.

2. Check Ubuntu version
cat /etc/os-release

Purpose: Shows the Linux distribution and version.

Step 2 — Filesystem Sanity
3. Create a temporary directory
mkdir /tmp/runbook-demo

Purpose: Checks whether the system can create a directory successfully.

4. Copy a file and verify it
cp /etc/hosts /tmp/runbook-demo/hosts-copy && ls -l /tmp/runbook-demo

Purpose: Checks file copying and verifies that the copied file exists.

Step 3 — CPU and Memory
5. Check CPU and running processes
top

Let it run for about 10 seconds.

Then press:

q

Purpose: Shows CPU usage, memory usage, load average, and running processes.

6. Check memory
free -h

Purpose: Shows total, used, free, available, and swap memory.

Step 4 — Disk / I/O
7. Check disk usage
df -h

Purpose: Shows available and used disk space for mounted filesystems.

8. Check log directory size
du -sh /var/log

Purpose: Shows how much disk space /var/log is using.

Step 5 — Network
9. Check listening ports
ss -tulpn

Purpose: Shows listening TCP/UDP ports and the processes using them.

10. Test network connectivity
ping -c 4 8.8.8.8

Purpose: Checks whether the system can reach an external IP address.

Step 6 — Check Target Service
11. Check Cron status
systemctl status cron

Look for:

Active: active (running)

Also note the:

Main PID

Purpose: Confirms whether the cron service is running correctly.

Step 7 — Check Cron Process
12. Check CPU and memory of Cron
ps -o pid,pcpu,pmem,comm -p $(pgrep cron)

You should get something similar to:

PID %CPU %MEM COMMAND
151 0.0  0.0  cron

The exact values will depend on your system.

Purpose: Checks whether the cron process is consuming unusual CPU or memory.

Step 8 — Check Cron Logs
13. View recent Cron logs
journalctl -u cron -n 50

Purpose: Shows the latest 50 log entries generated by the cron service.

Look for things such as:

ERROR
FAILED
WARNING

Also check whether scheduled jobs are running normally.

Step 9 — Check Traditional Log File

Depending on your Ubuntu setup, try:

tail -n 50 /var/log/syslog

Then look specifically for cron messages:

grep cron /var/log/syslog | tail -n 20

Purpose: Checks whether cron-related events are appearing in the system log.

If /var/log/syslog doesn't exist on your system, don't worry—we'll use journalctl as the primary log source.
